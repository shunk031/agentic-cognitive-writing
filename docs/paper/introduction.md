# Introduction

In the systems surveyed here, large language model agents draft entire articles, surveys, and research reports according to predetermined macro-stage orders that allow iteration and feedback within individual stages[^2][^3][^4][^7]. We use *agentic writing* for systems in which a large language model agent coordinates at least two distinct writing operations to produce or revise a document. In the same literature, the phrase appears only as a passing descriptor for intentional writing or an agentic assistant, rather than as a defined research object[^5][^6]. The surveyed literature has not tested which ordering of writing work makes an agent write well.

For human composing, we frame the order-of-work question through Flower and Hayes' Cognitive Process Theory of Writing[^1]. The theory describes a Monitor that coordinates Planning, Translating, and Reviewing through an evolving goal network while interacting with a task environment and long-term memory. Planning generates and organizes ideas and sets goals. Translating turns represented meanings into written language. Reviewing evaluates and revises text or plans. The Monitor may embed these processes within one another. Writers may regenerate higher-level goals as the developing text changes their understanding of the rhetorical problem. In our implementation analogy, these functions correspond to components available in modern agent systems: an orchestrator, delegated roles, and externalized project state.

CogWriter[^7] provides a theory-inspired precedent without testing this account. It frames planning, monitoring, and reviewing as cognitive writing, yet its released implementation[^8] runs a fixed top-level sequence from planning to generation. Its benchmark evaluation measures output performance rather than the theory's predictions.

We realize this analogy in Agentic CogWriter, an experimental instrument. Agentic CogWriter is independent of the existing CogWriter framework described above. The artifact is an installable, inspectable writing plugin whose adapters target two agentic coding platforms, Claude Code and OpenAI Codex. The system maps the Monitor, Planning, Translating, and Reviewing to executable roles. It externalizes the assignment, goals, draft, memory, and plans in project files. The process roles come from the 1981 theory. Their assignment to software files is our implementation interpretation.

The executable design permits controlled interventions unavailable in human studies. The no-goal-network ablation deletes the explicit goal-network artifact. Comparing this ablation with Agentic CogWriter isolates the contribution of explicit hierarchical goals. The fixed-order ablation constrains the main Planning, Translating, and Reviewing sequence while retaining Generate and Evaluate interruptions. After an interruption, the Monitor returns to the prescribed order. Comparing the fixed-order ablation with Agentic CogWriter isolates dynamic selection among the three main processes. An append-only JSON Lines trace records controller-produced process switches, goal events, decisions, evidence, and unresolved questions under the declared trace contract. The trace exposes only logged controller actions, not private model state. Missing or ambiguous events remain trace-quality findings.

A six-condition controlled comparison tests both writing quality and the theory's process predictions under equal information and fixed resource policies. The comparison includes the single-shot baseline, the linear Pre-Write/Write/Re-Write baseline, the STORM-style baseline without retrieval, Agentic CogWriter, the no-goal-network ablation, and the fixed-order ablation. The fixed-stage baselines are our large language model analogues of the stage organization that Flower and Hayes' theory[^1] challenged. The theory does not specify these baselines. The STORM-style baseline follows perspective discovery, simulated question answering, outlining, drafting, and polishing. STORM[^2] supplies the research-to-draft reference for this stage sequence. The baseline omits retrieval under the equal-information policy. The comparison poses four research questions:

1. **RQ1.** Does the theory-based recursive Monitor and goal-network architecture produce better writing than a single-shot system and linear-stage pipelines?
2. **RQ2.** Which components matter? We compare Agentic CogWriter with the no-goal-network ablation and the fixed-order ablation.
3. **RQ3.** Do agent traces, treated as an operational analogue of a thinking-aloud protocol that records observable writing actions rather than private cognition, show the goal creation and regeneration dynamics described by Flower and Hayes[^1]? Flower and Hayes predict that "an important difference between good and poor writers will be in both the quantity and quality of the middle range of goals they create."[^1] The analysis tests whether these goals, which connect broad rhetorical aims to local writing actions, relate to writing quality.
4. **RQ4.** Does the mapping replicate across platforms?

Our contributions are fourfold:

1. We operationalize a cognitive writing-process theory through persistent artifacts: an explicit goal network, Monitor-mediated dynamic process selection, and append-only traces of process switches, goal changes, and revision.
2. We instantiate the same process mapping for both host platforms through host-specific manifests and adapters.
3. We use component ablations and controller-action records governed by the declared trace contract to test the theory's process predictions alongside final text quality.
4. To our knowledge, among the systems surveyed in the supporting system survey (see Artifact availability), no prior system operationalizes the theory as persistent artifacts with an explicit goal network, uses Monitor-mediated dynamic process selection, records append-only traces, packages these mechanisms as an installable plugin, and tests the theory's predictions.
