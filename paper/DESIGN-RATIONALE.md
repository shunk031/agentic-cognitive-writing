# Design rationale

This entry point records only reasons stated in the repository's research and protocol documents. Where those documents record a setting without a reason, it says so.

- **Primary benchmarks.** The study uses WritingBench (Apache-2.0) for general-purpose writing, HelloBench (MIT) for long-text generation, and DoLoMiTes (Apache-2.0 and CC BY 4.0 materials) for structured expert writing. The survey records one benchmark for each writing kind, clear license signals, and a product-level evaluation path: WritingBench supplies query-specific criteria, HelloBench supplies long-text checklist evaluation, and DoLoMiTes supplies methodical expert tasks. The protocol fixes these three as the primary set. See [`writing-eval-datasets.md`](../docs/research/writing-eval-datasets.md) and [`protocol.md`](../docs/experiments/protocol.md).
- **Excluded candidates.** PERSUADE 2.0 and ICLE++ are prompt sources or human-score anchors, not primary benchmarks. LongBench-Write remains optional because benchmark-file licensing and provenance are unresolved. EQ-Bench remains a secondary creative probe because its license is unresolved; WildBench remains a broad-assistant subset rather than a pure writing benchmark; WritingPreferenceBench is a judge-sensitivity reference rather than a generation benchmark and has conflicting license metadata. LongGenBench is a supplementary long-context robustness probe, and LongJudgeBench validates judges rather than generated writing. ASAP is a prompt source and historical scoring reference with access terms to check. These roles and exclusions are recorded in [`writing-eval-datasets.md`](../docs/research/writing-eval-datasets.md) and [`protocol.md`](../docs/experiments/protocol.md).
- **DoLoMiTes split.** The study uses only the development subset. The prompt README records an archive-derived 820-dev/1,037-test split, says that the archive count is authoritative over the upstream README's 830-dev statement, and keeps the test subset out of primary analysis. The protocol gives no further reason for this development-only choice. See [`prompts/README.md`](../experiments/prompts/README.md) and [`protocol.md`](../docs/experiments/protocol.md).
- **Hard prompt slice.** The protocol records a 300-prompt hard set. The prompt README records the selection key: prompt word count plus the largest requested length matched in `prompt_text` and then the JSON dump of `requested_output_constraints`, using `words`, `字`, or `tokens`; prompts above 6,000 prompt words or requested length are excluded, and candidates are sorted by descending score, prompt-word count, requested length, and prompt ID. The documents do not record an additional reason for the 300-prompt size. See [`prompts/README.md`](../experiments/prompts/README.md) and [`protocol.md`](../docs/experiments/protocol.md).
- **Estimands after the pilot.** A ten-prompt WritingBench pilot showed that the generic five-dimension scale saturated while benchmark-native criteria and pairwise comparisons discriminated among conditions. The protocol therefore assigns native and generic pointwise scores as descriptive outputs and pairwise preference as the confirmatory estimand; the session handoff records the pilot decision. See [`protocol.md`](../docs/experiments/protocol.md) and [issue 32](https://github.com/shunk031/agentic-cognitive-writing/issues/32).
- **Information and retrieval.** Every condition receives the same assignment, context, tools, context-window policy, timeout, output budget, and allowed attempts. The no-retrieval rule forbids web search, network retrieval, external browsing, and unprovided sources. The protocol records this as the equal-information policy and gives no separate reason beyond holding supplied information constant. See [`protocol.md`](../docs/experiments/protocol.md).
- **Seven conditions.** A1 is single-shot generation; A2 is the fixed Pre-Write/Write/Re-Write pipeline; A3 is an adaptive task-planning, WriteHERE-style baseline without retrieval; A4 is the proposed Agentic CogWriter plugin; A5 removes the explicit goal network; A6 retains the state but fixes process order; and A7 folds the work into one writer. The protocol records the provenance and behavior of each baseline. See [`protocol.md`](../docs/experiments/protocol.md).
- **Judge family.** The scored study uses one configured judge family per platform. The `allow_same_family_judge` setting defaults to `false`; setting it to `true` marks exploratory same-family scoring, and those scores do not enter confirmatory analysis. The protocol records the same-family scored study and the separate cross-family check; the repository does not record a further reason for the primary judge-family choice. See [`experiments/README.md`](../experiments/README.md) and [`protocol.md`](../docs/experiments/protocol.md).
- **Coding-agent harness.** The system packages the Monitor and role skills as a plugin with Planner, Translator, and Reviewer subagents, and the protocol maps those roles to the three writing processes. The ablations change process instructions or the Monitor's selection rule while keeping the shared framework, inputs, and tools fixed; the protocol records this as the way to test the account as an agent process. See [`skill-subagent-survey.md`](../docs/research/skill-subagent-survey.md) and [`protocol.md`](../docs/experiments/protocol.md).
- **Confirmatory family.** The prompt-collapsed outcome gives one semantic winner when both presentation orders agree and a tie for any disagreement, including winner versus tie. Ties leave the exact two-sided sign test, and Holm correction covers the 24 cells formed by eight locked contrasts across three replications for each benchmark. The protocol records these rules as the confirmatory estimand and family definition. See [`protocol.md`](../docs/experiments/protocol.md).
- **Replications.** The protocol defines three independent runs for the 24-cell family and keeps the replication analysis separate from primary scoring. The repository records the count and separation rule but gives no additional reason for choosing three. See [`protocol.md`](../docs/experiments/protocol.md).
