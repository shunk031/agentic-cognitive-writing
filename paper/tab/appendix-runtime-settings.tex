\paragraph{Runtime lock and isolation.}
The runtime was designed to hold information access and host configuration fixed across conditions. Before a scored run, the runner requires explicit model, decoding, budget, timeout, seed, version, plugin-commit, retry, and statistical settings; unresolved values stop execution before a model process is created. Conditions share the same assignment and supplied context, resource limits, and tool policy, while web search, network access, external retrieval, and unprovided sources are disabled. Per-run provider configuration is also isolated from local guidance, so the \condSingleWriter\ prompt's pointer to the repository's writing guidance had no target in the run workspace, and retries reuse the same prompt and policy rather than adding information or budget. These controls implement the study's equal-information policy and reduce hidden runtime state as a source of condition differences.
The runner also supports Claude Code as the harness, but every reported generation run uses Codex CLI.

\paragraph{Model roles.}
The study uses \modelGenBare\ for generation because the experiment requires high-volume long-form generation across many systems, prompts, and replications; the model is positioned for fast, cost-sensitive workloads within the GPT-5.6 family~\citep{openai2026gpt56,openai2026luna}. \modelJudgeBare\ is used as the higher-capability primary evaluator, consistent with its positioning for more demanding professional work~\citep{openai2026gpt56,openai2026sol}. Medium reasoning effort is held fixed rather than tuned within the reported study. For the primary judge, the first main run inherited the documented medium default, and later runs pin medium explicitly to reproduce the same reasoning level.

\paragraph{Compute reporting.}
The generator and both judges are hosted closed models whose parameter counts and provider-side accelerator configurations are not disclosed to us, so we cannot report model parameter counts or GPU-hours.
Instead, we report the model identifiers and roles, reasoning effort, output-token budget, retry policy, available token accounting, and wall-clock statistics recorded by the harness; these quantify observable consumption rather than provider-side compute.
No model weights are trained or fine-tuned in this study.

\paragraph{Evaluation controls.}
Pairwise outputs are blinded and judged in both presentation orders to reduce known position bias in LLM evaluation~\citep{zheng2023judging,wang2024fair}. The two orders are treated as repeated measurements of one prompt-level comparison rather than independent samples: a semantic winner is retained only when both orders agree, and any disagreement becomes a tie. Outputs from incomplete generations receive no scores: pointwise z-scores and means use only the scored outputs of each generation run and benchmark, paired quality differences use the prompts scored for both systems, the sign tests drop any pair with a missing output, and prompt-level means average a prompt over the generation runs in which its pair was judged. We report \modelCross\ separately as a cross-family robustness check rather than pooling it with the confirmatory judge, given evidence that model-family relationships can affect evaluator preferences~\citep{panickssery2024selfpreference}.

\paragraph{Frozen operational values.}
Three generation runs define the replication dimension of the pre-specified confirmatory analysis. The 64,000-token generator output budget, primary-judge seed, and two-retry judge policy are fixed operational settings, not tuned values. Generator temperature is reported as unset because the scored generation interface did not expose that control; unsupported generation controls were monitored rather than varied across conditions.
