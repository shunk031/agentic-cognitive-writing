\subsection{Systems compared}
\label{sec:baselines}

We evaluate the proposed architecture in three steps. First, we compare \condAgenticCogWriter\ with alternative ways of organizing long-form generation. Second, we modify components of \condAgenticCogWriter\ to test which parts of the design matter. Third, we analyze the realized writing-process traces to understand how the \texttt{Monitor} actually uses its freedom to choose the next writing activity. All pre-specified systems use the same generator, task inputs, coding-agent harness, information access, and final-output contract.

\paragraph{Alternative writing organizations.}
\condSinglePass\ generates the entire document in one model call and therefore makes no intermediate writing decision. \condStaged\ uses a fixed \texttt{Pre-Write}$\rightarrow$\texttt{Write}$\rightarrow$\texttt{Re-Write} workflow, following the common pattern of separating planning, drafting, and revision into prescribed stages~\cite{yang2022re3,wan2025cognitive}. \condTaskPlanning\ implements a WriteHERE-style adaptive task graph~\cite{xiong2025beyond}: the system recursively decomposes the writing task and chooses among dependency-satisfied task nodes. This baseline is adaptive, but the unit chosen next is a task node rather than a writing process. These systems are controlled re-implementations under our generator and harness, not executions of the published systems.

\paragraph{Process-level interventions.}
The full \condAgenticCogWriter\ keeps the shared draft, goal network, and process history; lets the \texttt{Monitor} choose the next writing process; and executes the selected process in the corresponding specialized role context. \condNoGoals\ removes the explicit goal network while keeping adaptive process selection and the three specialized role agents. \condFixedOrder\ keeps the shared records and role agents but removes process-order choice: it repeatedly executes \texttt{Planning}$\rightarrow$\texttt{Translating}$\rightarrow$\texttt{Reviewing}. These two interventions each target one theory-derived component of the full system.

\paragraph{Execution diagnostics.}
\condSingleWriter\ keeps adaptive process selection and the goal network but executes planning, drafting, and reviewing inside one writer context without subagent delegation. It also restricts each \texttt{Translating} step to one paragraph before the next process decision. Because this changes role separation, delegation, control granularity, and output length together, we interpret it only as a bundled diagnostic. After observing the primary results, we added \condSingleContext\ as a narrower exploratory check: it keeps the same process loop and shared state but executes each selected process in the host agent's context. Unlike \condSingleWriter, it does not impose the one-paragraph restriction. This run used a different gateway entry point and plain HTTP transport while keeping the generator model unchanged, so it is not a clean context-only intervention and remains outside the pre-specified confirmatory analysis.

\subsection{Benchmarks and prompts}
\label{sec:benchmarks}

We use WritingBench~\cite{wu2026writingbench}, HelloBench~\cite{que2024hellobench}, and DoLoMiTes~\cite{malaviya2025dolomites}. WritingBench covers general-purpose writing with task-specific criteria, HelloBench contains long-text generation tasks across several genres, and DoLoMiTes contains structured expert-writing tasks such as plans, reports, and design documents.

We evaluate a committed longest-output slice containing 100 prompts per benchmark, for 300 prompts total. Prompt selection is deterministic and fixed before generation: pilot prompts are excluded, and the remaining prompts are ranked using prompt length together with requested output length. This slice is intended to emphasize demanding long-form settings, so our conclusions concern the selected slice rather than the full benchmark distributions. Appendix~\ref{app:prompts} gives the complete selection rule, prompt provenance, and generation contracts. External retrieval is disabled for all conditions.

\subsection{Implementation and replications}
\label{sec:implementation}

Every prompt--system pair is generated in three independent replications. The common generator is \modelGen. The coding-agent harness records process switches, goal events, completed outputs, delegated invocations, token accounting, and timing. For \condAgenticCogWriter, the host agent serves as the \texttt{Monitor}, while the \texttt{Planner}, \texttt{Translator}, and \texttt{Reviewer} operate over the same shared workspace. Runtime settings are reported in Appendix~\ref{app:runtime}. The harness uses the host platforms' documented skills and subagent mechanisms~\cite{anthropicAgentSkills,anthropicSubagents,openaiBuildSkills,openaiSubagents,googleAntigravitySkills,googleAntigravitySubagents}.

\subsection{Evaluation}
\label{sec:evaluation}

\paragraph{Product-level scores.}
We first report the benchmark-native score where defined and a standardized pointwise product score for the initial replication. For the pointwise composite, each criterion score is standardized within benchmark and judge, then averaged across criteria and judges. These scores describe the quality of each system's outputs in isolation. They are secondary diagnostics rather than replicated confirmatory outcomes, and because they use our selected prompt slice and controlled re-implementations, we do not compare them numerically with published full-benchmark leaderboard values.

\paragraph{Matched-prompt pairwise preference.}
Our primary comparative outcome judges two outputs written for the same prompt. Each pair is evaluated in both presentation orders. If both orders select the same winner, that winner is retained; if the two orders disagree, the prompt is counted as a tie. We refer to this retained winner or tie as the \emph{prompt-collapsed outcome}. Prompts lacking a completed output from either system are excluded from that comparison.

The pre-specified plan called for a confirmatory judge from a different model family than the generator. The completed pre-specified contrast family instead uses \modelJudge, which shares the generator's model family. We therefore describe these as the primary pairwise results and reserve \modelCross\ for a descriptive cross-family robustness check rather than presenting it as a second confirmatory analysis.

\paragraph{Statistical testing.}
The pre-specified contrast family compares \condAgenticCogWriter\ with \condSinglePass, \condStaged, \condTaskPlanning, \condNoGoals, and \condFixedOrder; it also includes the diagnostic \condSingleWriter\ contrasts with \condSinglePass, \condAgenticCogWriter, and \condNoGoals. Each test is an exact two-sided sign test on wins and losses from one benchmark--contrast--replication cell, with ties excluded. Within each benchmark, Holm's procedure~\cite{dixonmood1946,holm1979} is applied jointly across all locked contrasts and replications. Prompts are not pooled across replications for inferential testing. The main tables instead show descriptive across-replication means; replicate-specific Wilson intervals~\cite{wilson1927} and Holm decisions appear in Appendix~\ref{app:pairwise-detail}.

\paragraph{Robustness and exploratory checks.}
We examine output-length sensitivity using two pre-specified matching bands and inference-compute sensitivity using cumulative output-plus-reasoning tokens. Because realized length and compute are consequences of execution, these analyses are descriptive rather than causal adjustments. The post-hoc \condSingleContext\ comparison is also exploratory. Finally, \modelCross\ provides a cross-family pairwise check on selected contrasts.

\paragraph{Process traces.}
For \condAgenticCogWriter\ and related process-level systems, we analyze observable execution events rather than latent reasoning. We count process transitions, goal creation, goal development, accepted goal regeneration, returns after \texttt{Reviewing}, and delegated invocations. We also split \condAgenticCogWriter\ runs by whether the realized sequence is exactly one \texttt{Planning}$\rightarrow$\texttt{Translating}$\rightarrow$\texttt{Reviewing} cycle and compare pairwise preference across the resulting groups. This trace-defined split is descriptive because realized behavior is not randomized.
