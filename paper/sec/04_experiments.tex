\subsection{Systems compared}
\label{sec:baselines}

The evaluation separates two questions: whether the proposed writing architecture improves over other ways of organizing generation, and which parts of \condAgenticCogWriter\ account for any difference. All pre-specified systems use the same generator, task input, coding-agent harness, available information, and final-output contract.

\paragraph{Alternative writing architectures.}
The one-shot baseline (\condSinglePass) asks the model to produce the complete document in a single call. The fixed-stage baseline (\condStaged) executes \texttt{Pre-Write}$\rightarrow$\texttt{Write}$\rightarrow$\texttt{Re-Write}, following the common pattern of separating planning, drafting, and revision into a prescribed workflow~\cite{yang2022re3,wan2025cognitive}. The adaptive task-planning baseline (\condTaskPlanning) follows a WriteHERE-style task graph~\cite{xiong2025beyond}: it recursively decomposes the assignment and selects among dependency-satisfied task nodes. This baseline is adaptive, but what it selects is a task node rather than a writing process. These baselines are controlled re-implementations under our common generator and harness rather than executions of the published systems.

\paragraph{Component variants of \condAgenticCogWriter.}
The full system uses the shared draft, goal network, and process history; chooses the next writing process online; and delegates that process to a specialized role agent. \condNoGoals\ removes the explicit goal network while retaining online process selection and the specialized agents. \condFixedOrder\ keeps the shared state and specialized agents but replaces online ordering with the repeated cycle \texttt{Planning}$\rightarrow$\texttt{Translating}$\rightarrow$\texttt{Reviewing}. These two variants test whether the explicit goal record and flexible process order are individually necessary for the full system's performance.

\paragraph{Execution variants.}
\condSingleWriter\ keeps online process selection and the goal network but performs planning, drafting, and reviewing in one writer context without subagent delegation. It also restricts each \texttt{Translating} step to one paragraph before the next process decision. Because several execution properties change together, we use it only as a diagnostic. After the primary results were observed, we added \condSingleContext\ as a narrower exploratory check. It preserves the same process loop and shared state but executes each selected activity in the host agent's context rather than a separate role-agent context, without the one-paragraph restriction. This run also used a different gateway entry point and plain HTTP transport, so it is not a clean context-only intervention.

\subsection{Benchmarks and prompts}
\label{sec:benchmarks}

We evaluate on WritingBench~\cite{wu2026writingbench}, HelloBench~\cite{que2024hellobench}, and DoLoMiTes~\cite{malaviya2025dolomites}. WritingBench covers general-purpose writing with task-specific criteria, HelloBench contains long-text generation tasks across several genres, and DoLoMiTes contains structured expert-writing tasks such as plans, reports, and design documents.

For each benchmark, we use a pre-committed slice of 100 prompts selected to emphasize long-output tasks, for 300 prompts total. Pilot prompts are excluded before ranking; the remaining prompts are selected deterministically from prompt length and requested output length. The resulting claims therefore concern this demanding long-form slice rather than the full benchmark distributions. Appendix~\ref{app:prompts} gives the complete selection procedure, prompt provenance, and generation contracts. External retrieval is disabled for every system.

\subsection{Generation setup}
\label{sec:implementation}

Each prompt--system pair is generated in three independent replications with \modelGen. The coding-agent harness records completed outputs, process switches, goal events, delegated invocations, token accounting, and timing. In \condAgenticCogWriter, the host agent serves as the \texttt{Monitor}; the \texttt{Planner}, \texttt{Translator}, and \texttt{Reviewer} read and update the same shared workspace. Runtime settings are reported in Appendix~\ref{app:runtime}. The implementation uses the host platforms' documented skill and subagent mechanisms~\cite{anthropicAgentSkills,anthropicSubagents,openaiBuildSkills,openaiSubagents,googleAntigravitySkills,googleAntigravitySubagents}.

\subsection{Evaluation}
\label{sec:evaluation}

\paragraph{Pointwise and benchmark-native quality.}
We first evaluate outputs independently. For the initial replication, we report each benchmark's native score where defined and a standardized pointwise composite. The composite standardizes each criterion within benchmark and judge and then averages across criteria and judges. These scores describe product quality under our controlled setup; they are not replicated confirmatory outcomes and should not be compared numerically with published full-benchmark leaderboard scores.

\paragraph{Matched-output preference.}
Our primary comparative evaluation judges two outputs written for the same prompt. Each pair is shown in both presentation orders. If both orders select the same winner, that winner is retained; if the two orders disagree, the prompt is counted as a tie. We call the resulting winner or tie the \emph{prompt-collapsed outcome}. Prompts lacking a completed output from either side are excluded from that comparison.

The locked analysis plan specified a judge from a different model family than the generator. The completed pre-specified contrast family instead uses \modelJudge, which shares the generator's model family. We therefore report these judgments transparently as the primary pairwise evaluation and use \modelCross\ only as a descriptive cross-family robustness check.

\paragraph{Pre-specified tests.}
The pre-specified contrast family compares \condAgenticCogWriter\ with \condSinglePass, \condStaged, \condTaskPlanning, \condNoGoals, and \condFixedOrder; it also includes \condSingleWriter\ comparisons with \condSinglePass, \condAgenticCogWriter, and \condNoGoals. Each test is an exact two-sided sign test on wins and losses from one benchmark--contrast--replication cell, excluding ties. Holm correction~\cite{dixonmood1946,holm1979} is applied within each benchmark jointly across all pre-specified contrasts and independent replications. Prompts are not pooled across replications for inferential testing. The main tables summarize replicate-specific win rates descriptively; Appendix~\ref{app:pairwise-detail} reports replicate-level Wilson intervals~\cite{wilson1927} and Holm decisions.

\paragraph{Robustness and trace analysis.}
We examine output-length sensitivity in two pre-specified matching bands and inference-compute sensitivity using cumulative output-plus-reasoning tokens. Because realized length and compute are consequences of execution, these are descriptive checks rather than causal adjustments. The post-hoc \condSingleContext\ comparison is also exploratory. Finally, we analyze observable execution traces from the process-organized systems: process transitions, goal creation and refinement, accepted goal regeneration, returns after \texttt{Reviewing}, and delegated invocations. We additionally compare outcomes for runs that realize exactly one \texttt{Planning}$\rightarrow$\texttt{Translating}$\rightarrow$\texttt{Reviewing} cycle with runs that realize another sequence. This trace-defined split is observational rather than randomized.
