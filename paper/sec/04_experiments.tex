\subsection{Conditions}
\label{sec:baselines}

All pre-specified conditions use the same generator and coding-agent harness. For RQ1, we compare four organizations of generation: \condSinglePass, \condStaged, \condTaskPlanning, and \condAgenticCogWriter. Starting from \condAgenticCogWriter, RQ2 then uses \condNoGoals\ and \condFixedOrder\ as confirmatory single-factor interventions, while \condSingleWriter\ serves as a bundled diagnostic intervention. After observing the primary results, we add \condSingleContext\ as a narrower post-hoc exploratory check on role-context separation. RQ3 uses the process and goal traces recorded during these runs rather than introducing another generation condition.

The first three conditions separate the presence of structure from the object of adaptive choice. \condSinglePass\ generates the document in one call and therefore makes no intermediate control decision. \condStaged\ executes a fixed \texttt{Pre-Write}$\rightarrow$\texttt{Write}$\rightarrow$\texttt{Re-Write} sequence inspired by staged long-form writing systems~\cite{yang2022re3,wan2025cognitive}: it introduces process-like stages but does not choose among them. \condTaskPlanning\ follows the adaptive task-planning pattern of WriteHERE~\cite{xiong2025beyond}, selecting dependency-satisfied nodes from an evolving task graph. It therefore provides adaptive control, but the choice is over task nodes rather than writing processes. These are controlled re-implementations on our generator and coding-agent harness rather than executions of the published systems.

\condAgenticCogWriter\ is the process-level condition defined in Section~\ref{sec:method-writing-processes}. It keeps the goal network, allows the \texttt{Monitor} to choose among \texttt{Planning}, \texttt{Translating}, and \texttt{Reviewing}, and executes the selected process with the corresponding \texttt{Planner}, \texttt{Translator}, or \texttt{Reviewer} role agent in separated role contexts. We derive three intervention conditions from it. \condNoGoals\ removes the explicit goal representation while retaining adaptive process choice and the three role agents. \condFixedOrder\ keeps the external records and separated role contexts but replaces adaptive process choice with a fixed \texttt{Planning}$\rightarrow$\texttt{Translating}$\rightarrow$\texttt{Reviewing} cycle. \condSingleWriter\ retains adaptive process choice and the goal network but executes all three processes in one writer context without subagent delegation. It also constrains each \texttt{Translating} step to add one paragraph before the next process decision. It therefore changes role-context separation, delegation, how much text is produced between process decisions, and output length together, and is a diagnostic ablation rather than a clean estimate of any one factor.

After observing the primary results, we added \condSingleContext\ as a post-hoc exploratory check on the interpretation of \condSingleWriter. \condSingleContext\ keeps the \texttt{Monitor}, the same \texttt{Planning}, \texttt{Translating}, and \texttt{Reviewing} instructions, the shared draft, goal network, process history, termination rule, and final-output contract, but executes each selected process in the host agent's context rather than delegating it to a separate role-agent context. Unlike \condSingleWriter, it does not impose the one-paragraph \texttt{Translating} restriction. The exploratory run also used a different gateway entry point and plain HTTP transport while keeping the generator model unchanged, so this comparison is narrower than \condSingleWriter\ but is not a perfectly isolated context-only intervention. We keep it outside the confirmatory family and use it only to test whether a simple attribution to separated role contexts survives this narrower check.

\subsection{Benchmarks and prompts}
\label{sec:benchmarks}

We use WritingBench~\cite{wu2026writingbench}, HelloBench~\cite{que2024hellobench}, and DoLoMiTes~\cite{malaviya2025dolomites}. WritingBench covers general-purpose writing with task-specific criteria, HelloBench contains long-text generation tasks across several genres, and DoLoMiTes contains structured expert-writing tasks such as plans, reports, and design documents. Their source pools contain 1,000, 647, and 820 prompts, respectively.

We select the 100 prompts per benchmark that request the longest outputs, for 300 prompts total. The ranking combines prompt word count with the largest explicitly requested output length; we exclude pilot identifiers and prompts requesting more than 6,000 words in either component. This longest-output slice is intended to make differences between control strategies easier to observe in long-form settings. The conclusions therefore concern this slice rather than the full benchmark distributions. All conditions receive the same prompt and benchmark information, and external retrieval is disabled.

\subsection{Implementation and replications}
\label{sec:implementation}

We hold the generator, task input, available information, tool availability, and final-output contract fixed across conditions. Every prompt--condition pair is generated in three independent replications. The generator is \modelGen; runtime details are reported in Appendix~\ref{app:runtime}.

The coding-agent harness uses the host platforms' documented skills and subagent mechanisms~\cite{anthropicAgentSkills,anthropicSubagents,openaiBuildSkills,openaiSubagents,googleAntigravitySkills,googleAntigravitySubagents}. For \condAgenticCogWriter, the host agent acts as the \texttt{Monitor}, while \texttt{Planner}, \texttt{Translator}, and \texttt{Reviewer} role agents operate over a shared working directory containing the draft, goal network, and process history. The same harness records process switches, goal events, completed outputs, delegated invocations, token accounting, and timing. All conditions return the complete document through the same output channel.

\subsection{Evaluation}
\label{sec:evaluation}

\paragraph{Product-level diagnostics.}
We report the benchmark-native score where defined and a standardized pointwise product score for the initial replication. For the pointwise composite, each criterion score is standardized within benchmark and judge, then averaged across criteria and judges. These scores situate the controlled conditions on conventional benchmark-level quality measures, so we present them first in Section~\ref{sec:results}. They are secondary diagnostics rather than the confirmatory outcome: they come from the selected longest-output slice and from our controlled re-implementations, so we do not compare them numerically with published full-benchmark leaderboard values.

\paragraph{Primary pairwise outcome.}
Our primary outcome is pairwise preference between two outputs for the same prompt. Each pair is judged in both presentation orders. If both orders select the same winner, that winner is retained; any disagreement becomes a tie. We call this single retained winner or tie the \emph{prompt-collapsed outcome}. Prompts lacking a completed output from either side are excluded.

The locked analysis plan called for a confirmatory judge from a different model family than the generator. The judgments used for the confirmatory contrast family reported here instead come from \modelJudge, which shares the generator's model family. We therefore scope the primary evidence to same-family judging and use \modelCross\ only as a descriptive cross-family robustness check.

\paragraph{Confirmatory contrasts.}
The pre-specified confirmatory family compares \condAgenticCogWriter\ with \condSinglePass, \condStaged, \condTaskPlanning, \condNoGoals, and \condFixedOrder; it also compares \condSingleWriter\ with \condSinglePass, \condAgenticCogWriter, and \condNoGoals. Across the resulting benchmark-by-contrast cells, we use exact two-sided sign tests on wins and losses and control family-wise error with Holm's procedure~\cite{dixonmood1946,holm1979}. We report pooled prompt-collapsed win rates across the independent replications with Wilson intervals~\cite{wilson1927}; replicate-specific cells show stability across generation runs.

\paragraph{Robustness and exploratory checks.}
We test output-length sensitivity using two pre-specified matching bands. We test inference-compute sensitivity using cumulative output-plus-reasoning tokens and symmetric compute-ratio bands; because realized compute is an outcome of execution, these analyses are descriptive robustness checks rather than causal adjustment. We report \condSingleContext\ as a post-hoc exploratory check outside the confirmatory family. Finally, \modelCross\ provides a cross-family pairwise check on selected contrasts. Its results are descriptive rather than a second confirmatory family.

\paragraph{Process traces.}
To answer RQ3, we analyze observable process and goal events rather than latent reasoning. We count process transitions, goal creation, development and regeneration, returns after \texttt{Reviewing}, and delegated invocations. Task-graph events from \condTaskPlanning\ are kept separate from writing-process events because the two conditions make different kinds of next-step decisions.
