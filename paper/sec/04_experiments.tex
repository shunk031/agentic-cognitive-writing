\subsection{Research questions}
\label{sec:research-questions}

We ask two questions. \textbf{RQ1} asks whether making writing processes the controller's action space improves long-form writing relative to generation with no intermediate choice, a fixed stage sequence, and adaptive choice over task nodes. \textbf{RQ2} asks which theory-derived commitments account for any improvement: an explicit goal representation, adaptive process ordering, or separated role contexts. We use process traces to interpret RQ2 rather than treating trace behavior as a separate product claim.

\subsection{Conditions}
\label{sec:baselines}

We compare seven experimental conditions under the same generator and coding-agent harness.

The first three conditions separate the presence of structure from the object of adaptive choice. \condSinglePass\ generates the document in one call and therefore makes no intermediate control decision. \condStaged\ executes a fixed \texttt{Pre-Write}$\rightarrow$\texttt{Write}$\rightarrow$\texttt{Re-Write} sequence: it introduces process-like stages but does not choose among them. \condTaskPlanning\ follows the adaptive task-planning pattern of WriteHERE~\cite{xiong2025beyond}, selecting dependency-satisfied nodes from an evolving task graph. It therefore provides adaptive control, but the choice is over task nodes rather than writing processes. These are controlled re-implementations on our generator and coding-agent harness rather than executions of the published systems.

The fourth condition is Agentic CogWriter as defined in Section~\ref{sec:method-writing-processes}. It keeps the goal network, allows the \texttt{Monitor} to choose among \texttt{Planning}, \texttt{Translating}, and \texttt{Reviewing}, and executes the selected process in its corresponding role context. We derive three intervention conditions from it. \condNoGoals\ removes the explicit goal representation while retaining adaptive process choice and separated role contexts. \condFixedOrder\ keeps the external records and role contexts but replaces adaptive process choice with a fixed \texttt{Planning}$\rightarrow$\texttt{Translating}$\rightarrow$\texttt{Reviewing} cycle. \condSingleWriter\ keeps adaptive process choice and the goal network but executes all three processes in one writer context at paragraph granularity. Because it also changes recursion granularity, \condSingleWriter\ is a diagnostic ablation rather than a clean estimate of the effect of separated role contexts.

\subsection{Benchmarks and prompts}
\label{sec:benchmarks}

We use WritingBench~\cite{wu2026writingbench}, HelloBench~\cite{que2024hellobench}, and DoLoMiTes~\cite{malaviya2025dolomites}. WritingBench covers general-purpose writing with task-specific criteria, HelloBench contains long-text generation tasks across several genres, and DoLoMiTes contains structured expert-writing tasks such as plans, reports, and design documents. Their source pools contain 1,000, 647, and 820 prompts, respectively.

We select the 100 prompts per benchmark that request the longest outputs, for 300 prompts total. The ranking combines prompt word count with the largest explicitly requested output length; we exclude pilot identifiers and prompts requesting more than 6,000 words in either component. This longest-output slice is intended to make differences between control strategies easier to observe in long-form settings. The conclusions therefore concern this slice rather than the full benchmark distributions. All conditions receive the same prompt and benchmark information, and external retrieval is disabled.

\subsection{Controlled implementation}
\label{sec:implementation}

We hold the generator, task input, available information, tool availability, and final-output contract fixed across conditions. Every prompt--condition pair is generated in three independent replications. The generator is \modelGen; runtime details are reported in Appendix~\ref{app:runtime}.

The coding-agent harness uses the host platforms' documented skills and subagent mechanisms~\cite{anthropicAgentSkills,anthropicSubagents,openaiBuildSkills,openaiSubagents,googleAntigravitySkills,googleAntigravitySubagents}. For Agentic CogWriter, the host agent acts as the \texttt{Monitor}, while \texttt{Planner}, \texttt{Translator}, and \texttt{Reviewer} subagents operate over a shared working directory containing the draft, goal network, and process history. The same harness records process switches, goal events, completed outputs, delegated invocations, token accounting, and timing. All conditions return the complete document through the same output channel.

\subsection{Evaluation}
\label{sec:evaluation}

\paragraph{Primary outcome.}
Our confirmatory outcome is pairwise preference between two outputs for the same prompt. The judge is \modelJudge, which shares the generator's model family; primary claims are therefore conditional on same-family judging. Each pair is judged in both presentation orders. If both orders select the same winner, that winner is retained; any disagreement becomes a tie. Prompts lacking a completed output from either side are excluded.

The locked confirmatory family contains eight contrasts: \condFull\ versus \condSinglePass, \condStaged, \condTaskPlanning, \condNoGoals, and \condFixedOrder; and \condSingleWriter\ versus \condSinglePass, \condFull, and \condNoGoals. Across three benchmarks this yields 24 benchmark-by-contrast cells. We use exact two-sided sign tests on wins and losses and control family-wise error with Holm's procedure~\cite{dixonmood1946,holm1979}. We report pooled prompt-collapsed win rates across the three replications with 95\% Wilson intervals~\cite{wilson1927}; replicate-specific cells show stability across generation runs.

\paragraph{Secondary outcomes and robustness.}
Benchmark-native and pointwise scores are secondary diagnostics from the first replication. We test output-length sensitivity using 5\% and 10\% matching bands. We test inference-compute sensitivity using cumulative output-plus-reasoning tokens and symmetric compute-ratio bands; because realized compute is an outcome of execution, these analyses are descriptive robustness checks rather than causal adjustment. Finally, \modelCross\ provides a cross-family pairwise check on selected contrasts. Its results are descriptive rather than a second confirmatory family.

\paragraph{Process traces.}
To interpret RQ2, we analyze observable process and goal events rather than latent reasoning. We count process transitions, goal creation, development and regeneration, returns after \texttt{Reviewing}, and delegated invocations. Task-graph events from \condTaskPlanning\ are kept separate from writing-process events because the two conditions make different kinds of next-step decisions.
