We introduce \condAgenticCogWriter, a long-form writing system that turns document production into a stateful loop over explicit writing processes. Each run begins with a fixed writing task
\begin{equation}
X=(I,C,O),
\end{equation}
where $I$ is the instruction, $C$ is the supplied context, and $O$ is the requested output contract. Every writing process can read $X$, but only the document state changes during composition. Figure~\ref{fig:agentic-cogwriter} gives the system overview. One top-level \texttt{Monitor} agent coordinates three subagents: \texttt{Planner}, \texttt{Translator}, and \texttt{Reviewer}.

\subsection{Persistent Writing State}
\label{sec:method-control-state}

Composition produces a sequence of evolving drafts $D_0,D_1,\ldots,D_t,\ldots$ rather than a fixed number of predetermined stages. At writing step $t$, the shared workspace exposes
\begin{equation}
S_t=(D_t,G_t,H_t),
\end{equation}
where $D_t$ is the current draft, $G_t$ is the current hierarchy of writing goals, and $H_t$ is the observable process history. We use $D_0$ for the initial draft, which is empty unless the task provides one, and initialize $G_0$ from the assignment. Keeping these records outside any single agent context lets successive writing processes inspect and modify the same document-level state.

We represent writing goals explicitly as a hierarchy $G_t$. This goal network is motivated by \citet{flower1981cognitive}, who describe writers as creating and developing goals during composition. In our implementation, goals can be created, developed, or replaced as the draft changes; we call replacement of an existing goal \emph{goal regeneration}. The representation makes this theory-derived design choice observable and testable without claiming that the language agent has a human-like cognitive state.

\subsection{Process-Level Control and Execution}
\label{sec:method-writing-processes}

The key architectural choice is what the \texttt{Monitor} selects next. Its action space $\mathcal{A}$ is
\begin{equation}
\mathcal{A}=\{\texttt{Planning},\texttt{Translating},\texttt{Reviewing}\},
\end{equation}
and we write the decision at writing step $t$ as
\begin{equation}
a_t=\pi_{\mathrm{Monitor}}(X,D_t,G_t,H_t), \qquad a_t\in\mathcal{A}.
\label{eq:monitor-policy}
\end{equation}
We retain \citet{flower1981cognitive}'s term \texttt{Translating} for the drafting activity. Unlike a section scheduler or task-graph controller, Eq.~\eqref{eq:monitor-policy} selects the kind of writing work to perform next.

If \texttt{Planning} is selected, the \texttt{Planner} gathers relevant material from the current task and draft, organizes it for the intended audience, and creates or develops writing goals. If \texttt{Translating} is selected, the \texttt{Translator} turns the current plan and active goals into prose within the delegated draft scope. If \texttt{Reviewing} is selected, the \texttt{Reviewer} evaluates the current draft against the task and active goals, revises within the delegated scope, and reports whether further planning, drafting, or review is needed.

Each subagent writes its changes to the shared workspace before control returns to the \texttt{Monitor}, yielding the next state $S_{t+1}$. Review feedback can recommend replacing a goal, but the \texttt{Monitor} decides whether to accept that change and records the decision in $H_t$. Because each decision is made from the updated state, the process order is not fixed: drafting can expose a structural problem that sends control back to planning, and reviewing can trigger another drafting or planning pass. After reviewing, the \texttt{Monitor} may instead terminate the loop and return the current draft as the completed document $D_{\mathrm{final}}$.
