Figure~\ref{fig:agentic-cogwriter} gives an overview of \condAgenticCogWriter. The input is a writing task together with any task-specific context and output constraints; the output is a completed document. The system runs on a coding-agent-style harness with a persistent workspace and subagent delegation. A host agent reads the current writing state, decides what kind of writing work should happen next, invokes the corresponding specialist, and repeats until the document is complete.

\subsection{Persistent writing state}
\label{sec:method-control-state}

The shared workspace contains three records. The \emph{draft} stores the document produced so far. The \emph{goal network} stores an explicit hierarchy of current writing goals. The \emph{process history} records which writing activities have been executed and how the explicit goals have changed. The original user instruction and task constraints remain available throughout the run and are not rewritten into this state.

The goal network is inspired by Flower and Hayes' account of writer-generated goals~\cite{flower1981cognitive}. In our implementation, goals may be created, refined, or replaced as writing proceeds; we call replacement of an existing goal \emph{goal regeneration}. These events are logged because they make one theory-derived design choice observable and testable. The goal network is an engineering representation used by the agent, not a claim about an underlying human-like cognitive state.

\subsection{Online process selection and delegation}
\label{sec:method-writing-processes}

At each iteration, the host agent acts as the \texttt{Monitor}. It inspects the shared workspace and chooses one of three writing activities: planning, drafting, or reviewing. We retain Flower and Hayes' term \texttt{Translating} for the drafting activity in the implementation. Accordingly, the available process actions are \texttt{Planning}, \texttt{Translating}, and \texttt{Reviewing}. We refer to the host agent's prompted next-activity decision as the \emph{process-selection policy}; it is not a separately trained policy model.

The selected activity is delegated to the corresponding role agent. The \texttt{Planner} develops goals and document structure. The \texttt{Translator} turns the current goals into prose in the shared draft. The \texttt{Reviewer} evaluates the draft against the task and active goals and can propose revisions or changes to the goal network. Each role agent writes its updates back to the shared workspace before returning control to the \texttt{Monitor}. A proposed goal replacement is accepted or rejected by the \texttt{Monitor} and recorded in the process history.

The process order is not fixed. Drafting can expose a structural problem that sends the system back to planning, and review can trigger either another drafting pass or renewed planning. A run terminates after review when the \texttt{Monitor} decides that no further writing activity is needed. This repeated state inspection and online process choice is the defining control loop of \condAgenticCogWriter; the experiments separately test whether the explicit goal record and flexible process order are necessary for its observed performance.
