We introduce \condAgenticCogWriter, a long-form writing system that turns document production into a stateful loop over explicit writing processes. Each run begins with a fixed writing task
\begin{equation}
X=(I,C,O),
\end{equation}
where $I$ is the instruction, $C$ is the supplied context, and $O$ is the requested output contract. Every writing process can read $X$, but only the document state changes during composition. Figure~\ref{fig:agentic-cogwriter} gives the system overview. One top-level \texttt{Monitor} agent coordinates three subagents: \texttt{Planner}, \texttt{Translator}, and \texttt{Reviewer}.

\subsection{Persistent Writing State}
\label{sec:method-control-state}

All four agents operate over a shared writing state. After $t$ completed process invocations, we denote the state by
\begin{equation}
S_t=(D_t,G_t,H_t),
\end{equation}
where $D_t$ is the current draft, $G_t$ is the current hierarchy of writing goals, and $H_t$ is the observable process history. The initial state contains the empty or task-provided draft and goals derived from the assignment. Storing these records in the shared workspace lets each subagent recover the same document-level context before performing its role.

The explicit goal representation makes one theory-derived design choice observable and testable. Following the writer-generated goals in \citet{flower1981cognitive}, goals can be created, developed, or replaced as the draft changes; we call replacement of the active goal hierarchy goal regeneration. We use the representation as an engineering mechanism that can be ablated and analyzed, not as a claim that the language agent has a human-like cognitive state.

\subsection{Process-Level Control}
\label{sec:method-writing-processes}

The \texttt{Monitor} agent decides which writing process should run next from the fixed task and current writing state. The available actions are
\begin{equation}
\mathcal{A}=\{\texttt{Planning},\texttt{Translating},\texttt{Reviewing}\},
\end{equation}
and the decision after state $S_t$ is
\begin{equation}
a_t=\pi_{\mathrm{Monitor}}(X,D_t,G_t,H_t), \qquad a_t\in\mathcal{A}.
\label{eq:monitor-policy}
\end{equation}
The notation $\pi_{\mathrm{Monitor}}$ denotes the runtime decision rule, not a separately trained policy model. We retain \citet{flower1981cognitive}'s term \texttt{Translating} for the drafting activity. Unlike a section scheduler or task-graph controller, Eq.~\eqref{eq:monitor-policy} chooses the kind of writing work to perform next.

Adaptive process selection allows the writing order to change as the document develops. Drafting can expose a structural problem that sends control back to planning, and reviewing can trigger either another drafting pass or another planning pass. After reviewing, the \texttt{Monitor} may instead terminate the loop and return the current draft as the completed document $D_{\mathrm{final}}$.

\subsection{Agent Roles and State Updates}
\label{sec:method-agents}

Role-specific subagents execute the process selected by the \texttt{Monitor}. The \texttt{Planner} develops document structure and goals, the \texttt{Translator} turns the current plan and goals into prose, and the \texttt{Reviewer} evaluates the draft against the task and active goals. Each subagent writes its changes to the shared workspace before control returns to the \texttt{Monitor}, yielding the next state $S_{t+1}$.

The \texttt{Monitor} remains responsible for coordination across role-specific updates. Review feedback can recommend changing a goal, but the \texttt{Monitor} decides whether to accept the change and records the decision in $H_t$. The experiments below evaluate the complete system first and then remove the explicit goal representation or adaptive process ordering to test how much each design choice contributes.
